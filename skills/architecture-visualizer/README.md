# Architecture Visualizer (`arch-viz`)

Turn software engineering architectures, system designs, feature flows, database migrations, and refactoring proposals into grounded, verifiable, and interactive offline visualizations.

Architecture Visualizer is a dependency-free CLI tool and agent skill for software engineers, software architects, and AI coding assistants. It generates standalone, single-file HTML workbenches and companion Markdown architecture reports that work completely offline in any modern browser.

## Core Capabilities

| Capability | What It Does |
| --- | --- |
| **Reading Workbench** | Header, trust strip, diagram canvas, and chapter rail for Overview, Walkthrough, Changes, Review, Evidence, Data, and Plan, with a component sheet. See [`references/workbench-guide.md`](references/workbench-guide.md). |
| **Grounded Evidence Verification** | Verifies `file`, `symbol`, `api`, `table`, `command`, `document`, and `assertion` locators against the filesystem, classifying status as `verified`, `unresolved`, `stale`, or `asserted`. |
| **Policy Engine & Findings** | Evaluates structural rules including `forbidden_dependency`, `required_dependency`, `layer_direction`, `cycle`, `fan_in`, `fan_out`, and required evidence. Surfaced as structured findings. |
| **Multi-Scenario Player** | Walkthrough track and chapter with numbered steps, parallel hops, decisions, outcome choices, payloads, and recovery paths. |
| **Review & Blast Radius** | Computes upstream and downstream blast radius for every modified component, tracking explicit assumptions, unresolved questions, and implementation task mappings. |
| **Deterministic Geometry Engine** | Default swimlanes with shared column slots, right-angled routes, crossing jumps, distributed ports, and collision-aware labels; columns and curves remain available. |
| **Deep Canvas Exploration** | Focus-neighbor and affected-path isolation, search across nodes and edges, fullscreen presentation mode, URL state synchronization, and model- and layout-specific `localStorage` position persistence. |
| **Offline Export Suite** | Exports to standalone HTML, inline SVG, 2× PNG (rasterized via browser canvas), Markdown architecture summary, and copyable Mermaid syntax. |
| **Accessibility & Motion** | Stacked reading rail below 900px, full keyboard navigation, non-color state indicators (kind icons, text badges, line dashes), and `prefers-reduced-motion` compliance. |
| **Dependency-Free CLI** | Zero runtime npm dependencies. Runs directly with Node.js 22+ standard library: `inspect`, `scaffold`, `validate`, `build`, `mermaid`, and `init`. |

`arch-viz validate --stamp` records `meta.groundedAt`; `--fresh` checks for evidence drift. Builds record `meta.builtFrom` and mark stale records with `staleSince`.

> **Target Compatibility**: Node.js 22+ is required only on the machine executing the Architecture Visualizer CLI. The repository or system being inspected may use an older Node version, another language/runtime, or a legacy stack. Architecture Visualizer reads repository evidence and emits standalone artifacts; it does not change the target project's runtime or dependencies.

## 5-Minute Quick Start

### 1. Initialize or Scaffold a Model

Create a blank specification:
```bash
node bin/arch-viz.js init my-architecture.json
```

Or draft a spec automatically from your git working tree and import statements:
```bash
node bin/arch-viz.js scaffold -o my-architecture.json --repo-root .
```

### 2. Validate Against Quality Gates

Run the 14-point quality gate and architectural policy checks:
```bash
node bin/arch-viz.js validate my-architecture.json --repo-root .
```

### 3. Compile the Offline Workbench

Compile into a standalone HTML file and companion Markdown documentation:
```bash
node bin/arch-viz.js build my-architecture.json -o dist/architecture.html --md dist/architecture.md --repo-root .
```

Open `dist/architecture.html` directly in any web browser. No web server, CDN, or build tools are required.

## Migrating from 2.x

- The default layout is now swimlanes (`layout: 'lanes'`, always top to bottom). Use `layout: 'columns'` (or `--direction LR|TB`, which selects columns) for the previous arrangement, or `--router curved` for the previous routes. Saved card positions from older builds are ignored.
- Shared links now use `#v=2&…`; v1 links still restore. Copy link is hidden in embedded viewers; view links work from the downloaded HTML file.
- The left navigator is removed: Search is in the Cmd/Ctrl+K palette, the outline and locators are in Evidence, findings in Review, and scenarios in Walkthrough.
- The inspector drawer is replaced by a component sheet in the reading rail. The Data Model and Plan tabs now live in the Data and Plan chapters.
- View tabs are replaced by the Structure, Evidence, Change, and Risk lens switcher. The Delta tab's Current / Proposed / Diff controls are in the Change lens key; Data flow is under Structure's Filters, and Sequence is in the palette.
- The Gate button is replaced by trust pills leading into Review. Focus/Impact buttons moved to Show neighbours / Show blast radius in the component sheet and palette. Present, Fullscreen, and Animate are palette commands.

## Model and Review Workflow

Architecture Visualizer enforces a disciplined engineering process:

```
INSPECT → MODEL → VALIDATE → BUILD → REVIEW → RELEASE
```

1. **Inspect Before Drawing**: Discover real code, interfaces, routes, and schemas using `inspect` or `scaffold`. Never invent ungrounded components.
2. **Model Accurately**: Build a version 2 specification (`schemaVersion: 2`). Normalization compatibility automatically upgrades legacy version 1 specifications on ingest.
3. **Separate Evidence from Inference**:
   - `VERIFIED`: Confirmed against filesystem code with valid locators.
   - `INFERRED`: Deduced from surrounding project conventions.
   - `ASSUMED`: Stated design assumptions tracked in `meta.assumptions`.
   - `UNKNOWN`: Unresolved ambiguities flagged in `meta.unresolvedQuestions`.
4. **Validate with Quality Gate**: Verify that label sizes fit cards, boundaries are balanced, routing avoids unnecessary crossings, and policies pass cleanly.
5. **Review Blast Radius & Findings**: Inspect upstream and downstream dependency impacts and address policy findings.
6. **Release Gate**: **Always obtain explicit user or stakeholder approval** on the proposal before modifying application source code.

For complete schema details, see [`references/model-schema.md`](references/model-schema.md).
For evidence locators and policies, see [`references/evidence-and-policies.md`](references/evidence-and-policies.md).
For scenario playback modeling, see [`references/scenario-authoring.md`](references/scenario-authoring.md).
For lifecycle gates and verification truth, see [`references/review-and-release.md`](references/review-and-release.md).

## CLI Reference

```bash
arch-viz inspect [dir]                                                                      # Detect framework, DB, and queue signatures
arch-viz scaffold [-o spec.json] [--base <ref>] [--repo-root .] [--ignore <prefix>]        # Draft a spec from git diffs and import dependencies
arch-viz validate <spec.json> [--strict] [--repo-root .] [--json] [--stamp | --fresh]     # Run 14-point quality gate and policy checks
arch-viz build <spec.json> [-o out.html] [--md out.md] [--strict] [--direction LR|TB]     # Build standalone HTML workbench and Markdown report
arch-viz mermaid <spec.json> [--view flowchart|sequence|er]                                # Export to Mermaid diagram syntax
arch-viz init [output.json]                                                                # Scaffold clean starter specification
```

- `--strict`: Treats quality gate and policy warnings as non-zero build failures (recommended for CI pipelines).
- `--repo-root <dir>`: Sets the base path where `VERIFIED` files and evidence locators are resolved on disk.
- `--stamp`: Records the current commit as `meta.groundedAt` after clean validation.
- `--fresh`: Verifies evidence freshness against `meta.groundedAt` and exits non-zero on drift. Use one of `--stamp` and `--fresh` per run: with both, `--stamp` wins and freshness is not checked.
- `--no-open` or `ARCH_VIZ_NO_OPEN=1`: Prevents automatic browser launch after building.

## Accessibility & Security

### Accessibility
- **Screen Reader & Keyboard Support**: Full keyboard control (`Tab`, `Enter`, `Space`, `Esc`, shortcut keys `F` fit, `0` reset, `+`/`-` zoom, `A` animate, `1`–`4` lenses, `?` help; arrows pan when idle, right/j and left/k navigate walkthrough steps).
- **Responsive Reading Rail**: From 900px the rail docks beside the canvas; below 900px the page stacks canvas, walkthrough track, and rail. Selecting a component scrolls its sheet into view.
- **Non-Color Perception**: Meaning is never conveyed by color alone. Uniform cards use kind icons; edge protocols use solid vs dashed strokes; lens states use text badges, borders, and line styles.
- **Reduced Motion**: Respects `prefers-reduced-motion`: highlights remain, the camera jumps instead of gliding, and walkthrough playback and moving particles are disabled.

### Security
- **No Secret Leakage**: Specifications must never contain passwords, private keys, API secrets, or session tokens in locators, assertions, or payloads.
- **XSS Prevention**: DOM text nodes and attribute insertions are strictly HTML-escaped.
- **Script Neutralization**: Embedded JSON payloads escape `<` characters as `\u003c`, preventing `</script>` tag injection from breaking out of script containers.
- **Safe Template Splicing**: Compiler avoids regex string replacement (`String.replace`), using single backward literal slicing to prevent `$1`/`$&` placeholder expansion bugs.

## Automated Testing & Performance

- **Automated Test Suite**: 129 automated tests covering schema normalization, edge cases, cross-reference validation, candidate-route scoring, layout determinism, injection resilience, CLI exit codes, and Markdown/Mermaid exporters.
- **Headless Chrome Validation**: Rendered DOM layout tests run across 320px, 768px, and 1440px viewports to verify boundary containment, arrowhead tangent alignment, and label overlap avoidance.
- **Local Reference Smoke Test**: A deterministic stress smoke test of 100 nodes and 250 edges in real headless Chrome measured **74ms** readiness on the maintainer machine. *(Reported strictly as a local reference measurement under specific hardware conditions, not a universal benchmark or performance guarantee.)*

## Known Limitations

- **No In-Browser Editor**: The generated page is a read-only exploration and review workbench. The JSON specification is the single source of truth.
- **No Collaboration Server or Hosted Sharing**: There is no hosted web service, database, or WebSocket collaboration backend. Visualizations are shared directly as standalone files.
- **No Force-Directed Layout**: The layout engine uses deterministic hierarchical ranks and barycenter crossing minimization. Node positions are reproducible and do not bounce.
- **No DOT or PDF Export**: Supported exports are HTML, SVG, PNG (via browser canvas), Markdown, and Mermaid.
- **Comprehension Budget**: Views with more than 25 nodes trigger a Quality Gate 1 glanceability warning, advising decomposition into subsystem views.
